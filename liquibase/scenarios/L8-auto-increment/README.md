# L8 — Auto-increment, identity, sequences

**Conflict:** each engine generates keys differently, and they behave differently when someone inserts an explicit id.

| | PostgreSQL | MySQL | SQL Server |
|---|---|---|---|
| `autoIncrement: true` | `GENERATED BY DEFAULT AS IDENTITY` | `AUTO_INCREMENT` | `IDENTITY(start, step)` |
| `incrementBy` | ✅ | ❌ **Liquibase validation error**: step is server-wide (`auto_increment_increment`) | ✅ |
| Sequences (`createSequence`) | ✅ `nextval('seq')` | ❌ none | ✅ `NEXT VALUE FOR seq` |
| `addAutoIncrement` on an existing column | ✅ creates a sequence + `DEFAULT nextval()` | ✅ `MODIFY ... AUTO_INCREMENT` | ❌ **not supported**: can't add `IDENTITY` to an existing column |
| Explicit id `INSERT (id, ...) VALUES (1003, ...)` | ✅ allowed | ✅ allowed | ❌ needs `SET IDENTITY_INSERT t ON` |
| Next generated id after that | **1003 → duplicate key!** | 1004 (counter jumps past max) | 1004 (counter jumps past max) |
| Last generated id | `INSERT ... RETURNING id` | `LAST_INSERT_ID()` | `OUTPUT inserted.id` / `SCOPE_IDENTITY()` |

**The PostgreSQL trap:** inserting explicit ids (data imports, copying rows between environments) doesn't move the sequence. The next normal insert collides with a duplicate-key error. Fix it after such imports:
```sql
SELECT setval(pg_get_serial_sequence('invoice', 'id'), (SELECT max(id) FROM invoice));
```

**Liquibase solution**
- `autoIncrement` + `startWith` is portable. Avoid `incrementBy`.
- `createSequence` and `valueSequenceNext` are portable **between PostgreSQL and SQL Server only**. Restrict the changeset with `dbms: postgresql, mssql`.
- `addAutoIncrement` is restricted to `dbms: postgresql, mysql`. On SQL Server, create a new table (or column) with `IDENTITY` and copy the data.

**Run**
```bash
./run.sh L8
./run.sh L8 postgres yaml sql    # compare the generated DDL
./run.sh L8 mssql yaml sql
```
