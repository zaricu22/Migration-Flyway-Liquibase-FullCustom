# L1 — Boolean

**Conflict:** there's no common boolean. Each engine has a different type and a different literal.

| | PostgreSQL | MySQL | SQL Server |
|---|---|---|---|
| Type generated for `boolean` | `BOOLEAN` | `TINYINT` | `bit` |
| Literal for `valueBoolean: true` | `TRUE` | `1` | `1` |
| `WHERE enabled` (bare predicate) | ✅ | ✅ (non-zero = true) | ❌ syntax error, needs `= 1` |
| Can store other values | No | **Yes**, any tinyint (e.g. 7) | No (0/1/NULL) |

Actual SQL generated by `update-sql`:
```sql
-- postgresql
CREATE TABLE public.feature_flag (..., enabled BOOLEAN DEFAULT FALSE NOT NULL, ...);
INSERT INTO public.feature_flag (id, name, enabled) VALUES (1, 'dark_mode', TRUE);
-- mysql
CREATE TABLE l1.feature_flag (..., enabled TINYINT DEFAULT 0 NOT NULL, ...);
INSERT INTO l1.feature_flag (id, name, enabled) VALUES (1, 'dark_mode', 1);
-- mssql
CREATE TABLE feature_flag (..., enabled bit CONSTRAINT DF_feature_flag_enabled DEFAULT 0 NOT NULL, ...);
INSERT INTO feature_flag (id, name, enabled) VALUES (1, 'dark_mode', 1);
```

**Liquibase solution**
- **Abstract type** `boolean` plus `defaultValueBoolean` / `valueBoolean`. Liquibase picks the type *and* the literal per engine.
- **Raw SQL isn't translated.** Changeset 3 needs two variants, selected with `dbms`: `TRUE` for PostgreSQL/MySQL and `1` for SQL Server. The `UPDATE SUMMARY` shows the other variant as *"Filtered out: DBMS mismatch"*.

**Also visible:** SQL Server gets a named default constraint (`DF_feature_flag_enabled`), and PK names differ per engine (`feature_flag_pkey` vs `PK_FEATURE_FLAG`). Name your constraints explicitly if later changesets have to drop them.

**Run**
```bash
./run.sh L1                  # all engines, YAML
./run.sh L1 all xml          # same with XML
./run.sh L1 mysql yaml sql   # show the generated SQL only
```
